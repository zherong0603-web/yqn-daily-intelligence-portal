# 跨境早知道 V4 每日自动化执行规则

这是现有 Codex 定时任务的唯一执行入口。内容规则以 `docs/automation/跨境早知道V4内容规则.md` 为最高优先级。

## 目标

每天北京时间 16:00，在同一个任务内完成“去重检查 → 行动窗口核验 → 24/72 小时候选研究 → 委员会选题 → 一账式写稿 → 三审三校 → V4 校验 → 受保护调度 → 钉钉“跨境咨询每日内容”群送达核验”。

## 每次执行

1. 用系统 `date` 取得 Asia/Shanghai 真实日期，读取 `docs/automation/跨境早知道V4内容规则.md`、正式样板 `data/codex-shadow/2026-11-11.crossborder-v4/06-final.md`、`config/crossborder-v2-intelligence.yaml` 和自动化 memory。
2. 先查本机 `logs/automation/.crossborder-v4-dws-group-state.json` 与运行日志。已有 `[crossborder-v4:dws-group-delivered]` 或状态 `DELIVERED` 时不再重复生成、不再重复发送；状态为 `ATTEMPTED` 且无验证送达时只记录阻塞。旧私聊和 GitHub Actions 标记仅用于历史迁移，不再触发新发送。
3. 检查 `data/codex-shadow/YYYY-MM-DD.crossborder-v2.json`。存在则先运行 `npm run crossborder:v2:build -- --file <file>`；日期错、校验失败或内容过期才重新研究。
4. 先查行动窗口，再搜 24 小时；只有 24 小时内不足以形成高质量主题时才扩至 72 小时。每条候选记录受影响对象、公告日、生效日、卖家操作截止日、时区、今天仍可执行的动作和原文证据。来源未标注时区时写“来源未标注”。消费者活动日期不得代替卖家操作截止日。找不到仍有行动价值的主题时换题。
5. 先去重并搜集 10–15 条候选。输出 5 条重点候选、分数和取舍理由，再记录卖家经营、内容主编、传播入口三个视角的判断和分歧。最终保留 1–3 条同一商业问题的新闻。美国信号出现时必须排在第一，不得为了地域凑数，不得用旧闻补位。
6. 每条入稿信号必须有至少一个 `market_signal`、至少一个 `fact_basis`。政策优先官方或平台第一方；媒体数据必须能追溯到原文或指数提供方。每个来源记录 1–6 个页面可见 `markers`，用于自动核验关键数字、金额和政策文字。`published_at` 必须是来源页面可见日期，不得用检索日期代替。博主爆料只进 `unverified_claims`。
7. 按顺序完成 `采集 → 初稿 → 编辑 → 一审一校 → 二审二校 → 三审三校 → 冻结终稿`。每轮记录审核角色或独立审核人、所审版本、问题、改法和复核结果。执行人与独立审核人分开。三审未过时回到选题或重写，不得直接进入调度。
8. 终稿必须包含行动窗口、四问一账、A/B 1–3 秒黄金钩子、90–120 秒共用纯文本口播和事实边界。校验器还必须满足 1–3 条、美国优先顺序、5 条评分候选、单期主题、金额计算、纯文本、日期和来源全部通过。
9. 在 `data/codex-shadow/YYYY-MM-DD.crossborder-v4/` 集中保存候选与来源、初稿、编辑稿、三审三校记录、冻结终稿、机器 build/review/source-check 和交付状态。为兼容现有入口在根目录生成的交付快照必须与单期目录终稿同版本，不得维护平行稿。
10. 运行 `npm run crossborder:v2:build -- --file data/codex-shadow/YYYY-MM-DD.crossborder-v2.json`，再运行 `npm run crossborder:v2:source-check -- --file <file>`。必须退出码 0、`content_valid=true`、`automated_blockers=[]`；正式发送前 source check 必须 `all_ok=true`。
11. 调度前再次确认当天无成功标记、无未确认 attempt；先默认干跑；正式发送只能运行 `npm run crossborder:v2:dispatch -- --date YYYY-MM-DD --live`。该入口只接受 `--date` 与 `--live`，使用本机已授权的钉钉 Workspace CLI，以个人身份发送固定群聊“跨境咨询每日内容”。发送前必须确认群名唯一解析；`dws auth status` 必须显示已登录。未登录或群名不唯一时只阻塞发送分支，不读取或记录 token。
12. 群聊发送必须使用每日固定幂等键 `crossborder-v4-group-YYYY-MM-DD` 和 `--wait-delivery`。命令必须返回 `DELIVERED`、`READ` 或 `UNREAD`，才能输出 `[crossborder-v4:dws-group-delivered]` 并记为成功。
13. 发送前把状态写为 `ATTEMPTED`；已有 `ATTEMPTED` 且无验证送达时禁止自动重试。已有 `DELIVERED` 则跳过。状态只记录日期、状态、幂等键和时间，不记录任何账号标识或凭据。
14. 将日期、搜索窗口、行动窗口、入选主题和市场、候选数量、三审结论、口播秒数、幂等键、送达状态和送达时间追加到 `logs/automation/yqn-2.md`。
15. 成功后把消息内容留在当前窗口供负责人审阅；CLI 必须返回已送达状态。

## 强制边界

- 只推送“跨境咨询每日内容”群聊，不发送到其他群聊，也不向私聊重复发送。
- 不读取、展示或记录任何 AppSecret、accessToken、robotCode、userId 或 `dws` 登录 token。
- 不发送旧稿，不修改日期伪装新稿，不跳过 90–120 秒和来源校验。
- 补充稿使用独立幂等键，不占用当天 16:00 主任务的发送状态。
- 美国优先是排序要求，不是编造美国新闻的理由；没有合格美国信号时记录原因。
