# YQN 工作日晨报正式执行规则

这是 Codex 主任务和兜底任务的唯一执行规则。旧 V1.4 云端生成、旧本机 watchdog 和 OpenAI API 链路都不是当前正式路线。

## 目标

在同一个任务内完成“去重检查 → 当天研究 → 生成 3 条 → 本地校验 → GitHub Actions 发送 → 精确确认”。不读取、展示或记录 webhook、secret、token 或 API key。

## 每次执行

1. 用系统 `date` 取得 Asia/Shanghai 真实日期，读取本文、`knowledge/yqn-capabilities.yaml`、`src/dingtalk/buildSellerProblemBrief.ts` 和自动化 memory。
2. 先查 GitHub Actions 当天 `DingTalk YQN Seller Problem Brief` runs。对每个已启用目标，只有日志包含精确的 `markdown message sent` 标记才算已发送。全部已发送则记录后结束，不重复生成。
3. 检查 `data/codex-shadow/YYYY-MM-DD.seller-problem.json`。存在就先构建校验；缺失、日期错或校验失败才重新研究。
4. 内容恰好 3 条：2 条 `us_warehouse`、1 条 `mexico_warehouse`、0 条 `us_mexico_bridge`。优先跨境电商、履约、仓储、承运商、平台和主要玩家；先查最近 7 天，不足扩大到 30 天。
5. 来源优先政府、平台、承运商、上市公司投资者关系等第一方页面。每条必须有 `market_signal` 或 `seller_signal`，并有 `fact_basis`；最近官方公告可同时承担 `market_signal` 与 `fact_basis`。不得为凑链接使用低质量来源。
6. 全部 `checked_at`、`generated_at` 的上海日期必须是当天；标题必须包含“X月X日”；`publication.proposed_send_at` 保持当天 08:45+08:00。
7. 运行 `npm run codex:seller-brief:build -- --file data/codex-shadow/YYYY-MM-DD.seller-problem.json`。只有退出码 0、`content_valid=true`、`automated_blockers=[]`、计数精确为 2/1/0 才能继续。
8. 再次检查当天无成功标记且无未确认 `formal webhook attempt`，然后运行 `npm run codex:seller-brief:dispatch -- --date YYYY-MM-DD`。记录 `dispatch_id`，精确找到新 run 并等待结束。
9. 只有 run 成功且每个已启用目标都出现精确发送成功标记才算交付。如已有 attempt 但没有 success，严禁自动重试，必须留下强提醒。
10. 将时间、是否重建、校验结果、`dispatch_id`、run 链接和每个目标结果追加到自动化 memory。成功后归档当前自动化任务；失败时不归档，保留精确失败环节。

## 强制边界

- 只表达 YQN 已确认的头程、仓储、配送、资料衔接和物流方案能力。
- 不承诺税务、认证、清关必过、平台赔付、固定价格、固定时效或利润结果。
- 不发送旧稿、不改日期伪装新稿、不因为赶时间绕过校验。
