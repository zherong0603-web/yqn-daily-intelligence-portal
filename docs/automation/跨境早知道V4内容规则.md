# 跨境早知道 V4 内容规则

本文件是《跨境早知道》当前最高优先级内容规则。本轮升级选题、写稿、审校和留档标准。技术入口、16:00 调度、群聊目标、去重、干跑和送达核验仍见 `docs/automation/工作日晨报执行规则.md`。

## 受众和行动窗口

核心受众是正在经营的跨境卖家老板、运营负责人和成长型卖家。每条候选先回答四个问题：

- 谁受影响，具体到市场、平台、商品、交易方向和适用条件。
- 今天还能做什么。
- 什么时候截止。
- 哪条原文能证明。

同时查清公告日、生效日和卖家操作截止日，三者在稿件中分开写。日期或后台期限属于哪个时区，必须写明。来源没有显示时区时，写“来源未标注”，不得自行换算成北京时间。

消费者活动开始日不能代替卖家报名、发货、入仓或履约截止日。常规窗口已过时，只讲有证据支持的例外或仍能执行的动作。找不到针对目标卖家、今天仍可执行的动作时，换题。

市场优先级为美国、墨西哥、欧洲。美国优先是排序要求，不得为了覆盖地域加入无关新闻。真实但与目标卖家无关的新闻必须淘汰。

## 先查重再筛选

先去重，再把相同事件的多篇说明合并为一条候选。每天搜集 10 至 15 条候选，交付 5 条高价值候选及取舍理由。每条候选按 100 分评分：

| 维度 | 分值 |
| --- | ---: |
| 目标卖家相关性 | 35 |
| 对赚钱或成本的实际影响 | 30 |
| 具体数字或真实经营案例 | 15 |
| 传播冲突与黄金 3 秒潜力 | 10 |
| 时效性 | 10 |

可验证性和行动窗口是硬门槛。分数只辅助内容主编判断，不能抵消硬门槛。75 分以上优先进入主稿，低于 60 分原则上不播。

候选委员会至少记录三个视角的判断和分歧：

- 卖家经营：影响哪个经营环节，今天能否行动，何时可以先不动。
- 内容主编：是否只能回答一个商业问题，前 10 秒是否听得懂，是否有无关信息。
- 传播入口：钩子是否有事实支撑，是否存在标题、数字或适用范围被误读的风险。

委员会结论必须落到“入选、淘汰、换题”之一。存在实质分歧时写清分歧和裁决依据，不能只留平均分。

## 一期一个主题

每期围绕一个商业问题，用 1 至 3 条有逻辑关联的新闻展开。允许一条重要新闻讲透 90 秒。禁止把不同国家、不同交易方向和不同利润链路的新闻机械拼成一期。

美国新闻不是入选理由。稿件必须核实适用国家、商品、交易方向、适用条件和受影响卖家。政策在当天正式生效时，可以引用此前公布但页面日期可见的原始公告作为事实依据，当前媒体或官方更新提供当天触发信号。

## 把稿写成卖家今天能用的一张账

主稿必须说清四件事：谁受影响、算哪笔账、今天先做什么、什么情况下先不用动。

每个经营判断尽量配一张卖家能用自家数据填的表或检查清单。表至少包含：

| 字段 | 要求 |
| --- | --- |
| 受影响对象 | 店铺、活动、订单、批次、达人、仓库或商品 |
| 当前状态和日期 | 当前阶段，以及公告日、生效日、签收日或后台截止日 |
| 钱或暴露口径 | 金额、比例、期限、成本项或现金流暴露 |
| 今天要做的动作 | 今天能完成的具体动作 |
| 需要核验的结果 | 去哪里查、记录哪一列、什么结果算完成 |
| 触发后的动作 | 达到什么条件才进入下一步，什么情况下先不动 |
| 时区与不确定项 | 来源时区，以及不能从链接推断的期限口径 |

必须区分三类信息：

- 官方事实：原文直接写明。
- 真实案例：有可追溯主体和页面证据。
- 假设算例：明确写“假设”，并写清没有计入哪些费用。

时间动作按触发点拆开写。“现在能准备”和“条件触发后才能做”不能混在一起。页面只给出日期、没有具体时刻或时区时，保留原口径，不补造截止时间。

## 黄金 3 秒和口播

A 版使用戏剧化商业场景，B 版使用犀利反常识表达。两个钩子分别控制在 1 至 3 秒，必须包含具体对象、冲突或数字，并使用同一份正文。栏目口号“两分钟，听懂跨境事！”放在钩子之后。

钩子后的前 10 秒必须让目标卖家听懂：这件事落在谁身上、发生了什么变化、为什么值得继续听。

禁止把指数、保额、保证金率或预期变化直接写成卖家已经发生的现金支出。必须明确这是保障额度、压力测试还是实际费用。

语言要短、口语化、有具体数字，节奏要快。正文可使用：

- “跨境卖家注意……”
- 一条稿使用“今天老王只讲一件事。”
- 两条稿使用“今天老王带你看两件事。”
- 三条稿使用“今天老王带你看三件事。”
- “第一……”以及必要的“第二……”“第三……”

每条新闻讲清事实、金额或比例、适用条件，以及卖家今天能执行的动作。专业术语要翻译成卖家能听懂的话，不得连续堆砌机构名、缩写和数字。

计算必须保留假设。例如保障额度不能写成保费，指数周涨幅不能写成每张订单实际被扣款。

禁止空泛评价，包括“流量增长不等于利润增长”“卖家要关注成本变化”“机会与挑战并存”。没有新增信息时直接收尾：

“我是老王，跨境生意，先算利润，再谈爆单。”

## 三审三校和版本链

生产顺序固定为：

`采集 → 初稿 → 编辑 → 一审一校 → 二审二校 → 三审三校 → 冻结终稿 → 进入原交付流程`

每次审核只审上一轮已经完成的版本。所有问题回写后，才进入下一轮。

1. 一审一校核对原文、适用范围、公告日、生效日、截止日、时区、数字和算式。发现日期、口径或适用条件错误时退回编辑。
2. 二审二校站在当天卖家的位置核对：动作是否来得及、是否可操作、去哪里查、记录什么、看到什么结果采取什么动作，以及什么情况下先不用动。
3. 三审三校逐句朗读终稿，核对标题、A/B 钩子、正文和表格是否一致；检查日期、数字、歧义、废话、连续堆数字和口播时长。

每轮必须记录：审核角色或独立审核人、所审版本、发现的问题、改法、复核结果。没有实际审核和复核时不得填写通过。执行人与独立审核人必须分开。选题不成立时换题，不能靠润色救稿。

进入原交付流程前还必须满足：

- A/B 黄金 3 秒有明确冲突或金额反差。
- 前 10 秒能听懂对象、变化和收听价值。
- 新闻只解决一个共同商业问题，没有混入无关新闻。
- 假设、保额、指数和预算没有被讲成实际费用或已实现结果。
- 每个核心结论都能回指原文，来源日期为页面可见日期。
- 卖家听完能获得至少一条今天可以核对或执行的新信息。

最终判断标准：内容主编愿意把稿子直接拿去录制。代码通过测试、自动化完成或消息送达都不能代替内容质量。

## 同一期集中留档

继续使用现有归档根目录 `data/codex-shadow/`。每期在根目录下建立一个单期目录：

`data/codex-shadow/YYYY-MM-DD.crossborder-v4/`

同一期至少集中保存：

- `00-candidates-and-sources.md`：10 至 15 条研究记录、5 条重点候选、评分、委员会意见和来源。
- `01-draft-v0.md`：未修改初稿。
- `02-editor-cut-v1.md`：编辑稿。
- `03-review-01-facts-v1.md`：一审一校记录。
- `04-review-02-action-v2.md`：二审二校记录。
- `05-review-03-final-v3.md`：三审三校记录。
- `06-final.md`：冻结终稿和对外交付正文。
- `06-delivery.md`：钉钉兼容的纯文本交付版。保留终稿全部事实和口播，不使用会被钉钉折叠的 Markdown 表格。
- `07-delivery.json`：只记录状态、时间、幂等键和核验证据，不记录账号标识或凭据。
- 机器生成的 build、review、source-check 和口播文本也放在同一目录。

为兼容现有调度入口而生成的旧路径文件只是交付快照，必须与单期目录中的 `06-delivery.md` 同版本。钉钉发送优先读取 `06-delivery.md`，并在发送前核对 5 条候选、A/B 和口播正文与 `06-final.md` 同一版本。不得在平行记录里维护不同版本。内部审核材料不塞进对外口播。

## 正式样板

自 2026-11-11 起，正式样板为 `data/codex-shadow/2026-11-11.crossborder-v4/06-final.md`，状态记录在同期目录 `09-approved-standard.json`。后续每日沿用该样板的行动窗口、委员会选题、可填写经营账、A/B 钩子、90 至 120 秒纯文本口播和三审三校结构。每日事实、主题和来源必须按当期重新研究，不能照搬样板中的事实。

## 每日输出

- 今日 5 条高价值候选，标注入选、淘汰和理由。
- 本期商业问题、行动窗口、最终主题和委员会结论。
- 一张可填写自家数据的经营账表或检查清单。
- A/B 黄金 3 秒。
- 一份 90 至 120 秒 HeyGen 纯文本口播正文，A/B 共用。
- 新闻原始来源、页面可见日期、关键数字、时区和事实边界。
- 三审三校记录和集中归档入口。

每日主稿与临时补充稿使用独立幂等键，补充稿不得占用或阻断 16:00 主任务的去重状态。
