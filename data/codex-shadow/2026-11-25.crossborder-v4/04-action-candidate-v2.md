## 今天查哪里和补哪几列

1. Seller Center → Orders → Returns。用PO或RMA查该退货，展开箭头看Return Details，核商品/数量、退货渠道、物流方法和当前可见信息；Received → View Returns仅筛已收，不是全部在途。
2. Returns dashboard按给定时间段下载已处理退货报告，官方FAQ说最多5000条previously processed returns，含退款渠道/原因等。多于上限按实际可用条件分批、核覆盖范围；未完成近期票另在Returns查，不能把缺行直接当无退货。
3. Payments → Transactions，用同PO/CO及type/date过滤退款交易；Statements的Download Payments Report可核PO、Order Line、Transaction Type、SKU和Refunded Retail Sales。按PO+行+数量处理多件/部分退，退款渠道不当退款金额，Pending/Settled不当买家到账证明。
4. 运单号到相应承运官网看原始首扫、后续轨迹和签收证明；用面单/退货详情实际可见的目的地址找对应退货中心。再向实际收货仓索取收件、RMA/运单映射、件数、质检与可售/处置记录。没有原生字段的列人工补证，不把API或WFS/加拿大报表列当本页面固定导出。
5. 地址设置原文路径：Shipping Profile → Returns → Return Centers。至少保留有效US中心，多个中心默认最近可能有SKU指定；核本票面单实际地址。地址无效导致转Walmart中心可有failed delivery fee，没有固定已扣金额。改配置不代表已生成面单/在途自动改道。
6. 对Walmart Customer Care退款等符合本票规则的情形，可在Returns查PO/RMA展开，核可用Dispute this return入口及说明；无按钮先核退款是否发生、是否已有争议/超窗等原因，转实际Seller Support工单，别为查账再次点Refund Now。别把此客服退款指南套全部退款渠道或保证赔偿。

## 退货经营账

每PO、订单行、退货编号/包裹分别一行，自建列与原始报表列分清：
1. PO/客户订单、订单行、SKU、退货编号/RMA、原售数量、申请/实际退款数量、预期回件数、币种与实际承运产品；多件/拆包不只用整单总额判重复。
2. 退款渠道/原因、当前退款状态、发起/显示时间、退款售额、实际结算扣项、其他调整及各自来源/时区。退款售额、结算净额、库存成本分列，不能相加认定亏损；买家到账另以其支付状态核，不从首扫推断。
3. 退运单、承运首扫、当前位置/预计到货、实际目的仓/地址/别名、签收时间/POD及原时区；对应本票面单而非习惯仓。
4. 仓库实际收件批次、运单/RMA映射、SKU、验收件数、差异、质检、可售/待检/处置状态和凭证；物流签收不等库存可售，不因平台退款自动加库存。
5. 退款响应/争议等本票未完成动作、起算依据、可见截止/时区、负责人、证据编号/工单及下次查件。页面不显示先补查，不自行给所有票套统一争议天数或以核账延期应退款。
6. 退运费、失败配送/其他费只记录真实明细与币种，未发生不编扣款；成本待定位不等实际丢失，不保证追回款或免除客户合格退款。

今天的异常分支：
- 已显示退款、物流正常在途：分记资金和在途，留负责人及下次查件时间。先不重复手退、不预记可售，不把正常路途当立即可索赔。
- 已签收但仓库无记录：核实际目的地址和POD，找对应仓查卸货/收件批次及RMA映射、件数；若在另一中心，不能只等常用仓。仍不明时保存证据联系仓库/承运和平台支持，按本票条件升级，留工单与复查，不直接认定欺诈。
- 已收件未验收入库：仓库及时核SKU/数量/状态，不合格先待检；同时运营处理该票应退责任，不能等质检完才起算48小时或拖过时限。
- 金额/重复交易异常：先核订单行、数量、部分退/其他调整、币种、渠道，再比Returns与Payments凭证。符合本票规则才走争议；入口不适用或无按钮走支持，不手动再退或承诺一定赔。
- 地址无效/停用：先核已生成标签及包裹实际去向，再联系有关仓库/承运/支持，更正未来设置；不要求买家擅自改寄，不以后台修改当现有包裹已改道。
运营计算口径：同币种同PO+行退款售额按实际refund行合计；待定位数量=本票应回数量-已验收数量。出现负数、重复或不等先核多件/拆件映射，正常在途只标状态。退款额（美元或实币）与库存成本、结算净额不能直接加总叫亏损，此表不替代财务账务处理。
验收：钱的订单行/数量与退款证据、退件的运单/实际地址、实物验收/质检、本票动作截止与时区、负责人/下次复核均能回指记录；缺项填待核，不凭一张退款截图认定丢货或可售。

## 口播正文

美国沃尔玛自发货，货没回海外仓，先把退款和库存成本分开对。从沃尔玛网页或客服发起的适用退货，承运人首次扫描就触发退款，不能等仓库收齐才看钱。

今天进卖家中心，打开Orders下面的Returns，按PO号或退货编号查详情。再去Payments里的Transactions，对同一订单行的退款交易。多件、部分退，按行和数量核，别整单重复算。

用一张表分开记：退款状态和金额、退货运单首扫、实际目的仓、签收、仓库验收数量。下载已处理退货报告辅助核对，未完成的单另查，别当成一张全量在途表。

正常在途，记下负责人和下次查件时间，先别重复退款，也别提前加回可售。显示签收，仓库却没记录，就拿实际目的地址和签收凭证，让仓库查批次、件数。多个退货中心，别只等常用仓。

退款金额或重复交易有异常，带PO、订单行和交易凭证，按这票资格和时限走争议或平台支持。正常在途不代表立刻能索赔，也不保证工单一定赔。

未走自动退款的标准件，退货中心收件后48小时内要按规则发起退款，别拿核账拖退款。门店、平台仓、免退货和换货另外核，这张账先只看实际寄回的普通自发货退件。
